# 首页顶部改版设计说明

## 1. 目标
- 将首页顶部改为与用户截图一致的黑金舞台式视觉节奏。
- 本次仅改造截图范围内模块：首屏、轮播展示区、杭州小莲花展示区。
- 截图以下的既有首页模块保持现状，避免扩大改动范围。
- 文案先按截图语气与现有品牌语境拟定一版，后续可替换为正式文案。

## 2. 范围

### 包含
- 首页首屏 Hero 的视觉与内容重构。
- Hero 下方第一屏内容区改为横向轮播式展示模块。
- 新增杭州小莲花专题展示模块。
- 调整首页顶部几个模块之间的间距、背景过渡与层次关系。
- 接入目录 `官网首页素材/首屏` 与 `官网首页素材/杭州小莲花` 中的图片素材。

### 不包含
- 站点导航结构、路由结构、页脚结构调整。
- 截图以下的既有首页 section 重写。
- 新增后台配置、CMS 字段、接口或数据库改造。
- 多语言内容体系重构；本次先以中文文案为主，英文可先沿用旧逻辑或占位。

## 3. 现状判断
- 当前首页由 `HomePage` 顺序组合多个 section 构成，顶部依次为 `HeroSection`、`ManifestoSection`、`DomainCardsSection`。
- 当前顶部首页更偏“叙事 + 功能卡片”结构，与截图中的“主视觉 + 内容轮播 + 专题卡片”结构差异较大。
- 当前站点已经具备固定头部、深色金色主题、滚动入场动画和容器规范，这些能力可以复用，不需要推翻整站样式体系。

## 4. 设计方案

### 4.1 页面编排
首页顶部改版后的顺序如下：

1. Hero 主视觉区
2. 轮播展示区
3. 杭州小莲花专题区
4. 继续衔接现有首页后续模块

说明：
- 现有 `HeroSection`、`ManifestoSection`、`DomainCardsSection` 不再直接出现在首页顶部。
- 为降低风险，不删除这些旧 section 文件；本次仅调整首页组合方式。
- 首页后续现有模块继续保留，例如生态矩阵、新闻预告、最终 CTA。

### 4.2 Hero 主视觉区
- 使用 `官网首页素材/首屏/主屏背景.jpg` 作为主背景。
- 使用 `官网首页素材/首屏/标题.png` 作为主标题视觉，不再完全依赖纯文本大标题。
- 使用 `官网首页素材/首屏/了解详情.png` 作为主按钮视觉资源。
- `官网首页素材/首屏/椭圆-1.png` 作为局部高光或装饰层，增强截图中的金色能量环氛围。
- 保留固定头部导航，Hero 顶部留出安全空间，避免与头部重叠。
- Hero 文案结构维持轻量：品牌短句、主标题图、简短辅助说明、行动按钮。
- 首屏高度优先接近全屏，桌面端突出中心聚焦感，移动端转为纵向居中排布。

### 4.3 轮播展示区
- 采用“内容卡片轮播”而非传统整屏 banner 轮播。
- 桌面端优先呈现三卡并列或主卡 + 辅卡的横向结构，视觉参考用户截图右侧。
- 每张卡片使用深色玻璃面板、微弱金色描边、低饱和背景图层。
- 第一版先内置 3 组内容数据，不依赖后台接口。
- 交互以手动切换为主，可使用横向滑动、按钮切换或分页点；不要求复杂自动播放。
- 文案先按品牌表达拟定，重点体现“少年之印”“时代之印”“武印之印”一类主题感。

### 4.4 杭州小莲花专题区
- 使用 `官网首页素材/杭州小莲花/图层-0.png` 作为核心视觉。
- 使用 `官网首页素材/杭州小莲花/了解详情.png` 作为按钮视觉。
- 左侧为专题信息卡，右侧为视觉展示区，整体采用圆角卡片容器。
- 左侧信息卡包含：地点标题、活动定位、两到三项关键数字、简短说明、按钮。
- 右侧展示区保留一块内容承载面板，第一版可放主题图或视觉占位，不强行填满过多文字。
- 模块整体要有暖金渐变底光，突出截图中的舞台灯光感。

### 4.5 与旧首页衔接
- 杭州小莲花模块结束后，直接衔接现有保留 section。
- 衔接处需要通过背景渐变和上下留白过渡，避免新旧模块断层。
- 如果旧 section 的首屏间距过大，允许做轻微 margin 或 padding 调整，但不重写内容结构。

## 5. 技术设计

### 5.1 组件策略
- 新增首页顶部组合模块，例如：
  - `src/sections/home-top/HomeHeroStage.tsx`
  - `src/sections/home-top/HomeFeatureCarousel.tsx`
  - `src/sections/home-top/HomeLotusShowcase.tsx`
- `HomePage` 负责重新组合顶部 section，不在旧 section 文件里做硬改。
- 若需要共享装饰样式，可新增小型辅助组件，但避免抽象过度。

### 5.2 素材接入
- 素材以本地静态导入方式接入，避免额外远程依赖。
- 素材目录名包含中文，允许直接使用相对路径导入。
- 按钮素材如果尺寸固定，则通过 `img` 渲染，外层包裹可点击元素以保证交互语义。
- 装饰图层使用绝对定位并控制透明度，避免影响主内容可读性。

### 5.3 样式策略
- 继续使用 Tailwind CSS 与现有全局 token，不另起一套主题系统。
- 新增少量首页顶部专用类名时，优先写入 `src/index.css`，用于：
  - 背景发光
  - 轻微漂浮或入场动画
  - 轮播位移或遮罩
- 风格基调保持黑底、金色高光、低透明描边、弱玻璃质感。

### 5.4 响应式
- 桌面端优先还原截图的横向信息布局。
- 平板端允许轮播区和专题区从双列降为单列。
- 移动端 Hero 仍保留主视觉和按钮，但减少装饰层数量，避免首屏过高。
- 移动端轮播区改为单卡滑动或纵向堆叠，保证可读性优先。

## 6. 数据与文案
- 本次改版不依赖接口返回数据，顶部模块使用本地常量数据即可。
- Hero 使用品牌主标题与一句辅助说明。
- 轮播区使用 3 组本地卡片文案。
- 杭州小莲花区使用本地专题数据与数字标签。
- 后续若用户提供正式文案，可再替换为配置化内容。

## 7. 动效与交互
- 保留现有页面入场与滚动 reveal 风格，但降低复杂度，避免顶部过于花哨。
- Hero 可有轻微背景呼吸感或装饰层漂浮，不引入视频背景。
- 轮播区支持基础切换反馈，切换动画以淡入、平移或滚动吸附为主。
- 按钮、卡片 hover 使用现有站点的金色发光体系。

## 8. 无障碍与稳定性
- 所有非纯装饰图片应提供合适的 `alt` 策略；纯装饰图可置空。
- 图片按钮外层应使用真实按钮或链接元素，避免仅凭图片承担交互。
- 轮播切换控件需要可键盘聚焦。
- 若素材加载失败，应允许模块退化为纯色背景和文本布局，不影响页面可访问性。

## 9. 测试与验收

### 功能验收
- 首页加载后顶部顺序为 Hero、轮播区、杭州小莲花区。
- 导航、已有路由和下方既有模块不受影响。
- 按钮可点击，轮播区可切换。

### 视觉验收
- 桌面端整体观感接近用户截图中的黑金舞台风格。
- Hero、轮播区、杭州小莲花区层次分明，且与下方旧模块衔接自然。
- 素材比例正常，无明显拉伸或错位。

### 响应式验收
- 1440px 左右桌面端布局完整。
- 1024px 左右平板端不拥挤。
- 768px 及以下移动端内容可顺序阅读，按钮可点击。

## 10. 实施边界
- 本次实现优先达成“结构与视觉接近截图”的第一版。
- 不追求完全逐像素复刻截图。
- 不在本轮处理后台可配置化。
- 若用户后续继续补充素材，再按同样方式逐步替换截图以下区域。
